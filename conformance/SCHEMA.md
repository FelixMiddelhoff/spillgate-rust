# Conformance corpus schema

The corpus is the language-neutral proof that an implementation follows `spec/SPEC.md`. Every port runs it unchanged.

## Layout

```
conformance/
  SCHEMA.md
  manifest.schema.json        JSON Schema (draft 2020-12) of manifest.json
  manifest.json               the vector list
  vectors/small/              committed golden inputs (kilobytes), byte-exact, never normalized
  vectors/large/              NOT committed; generated, shipped as a release asset (see below)
```

## Corpus versions

`corpus_version` is a semantic version. Adding vectors bumps the minor version. Changing or removing an expected outcome bumps the major version and needs the user's sign-off (quality policy rule 3). Releases publish `spillgate-conformance-<version>.tar.gz` with a SHA-256 file. Ports pin one version.

## Manifest

```json
{
  "schema_version": 1,
  "corpus_version": "0.1.0",
  "vectors": [ { ...vector... } ]
}
```

### Vector fields

| Field | Type | Required | Meaning |
|-------|------|----------|---------|
| `id` | string | yes | Unique, `SG-V-<family>-<nnnn>`; never reused. |
| `description` | string | yes | What this vector attacks or checks. |
| `rules` | string[] | yes | SPEC rule/invariant IDs it covers, e.g. `["SG-R-LAY-03","SG-I-01"]`. At least one. |
| `refs` | string[] | no | Advisory IDs, e.g. `["CVE-2026-42587"]`. |
| `tags` | string[] | no | Free tags (`bomb`, `chain`, `boundary`, `header`, `malformed`, ...). |
| `tier` | `"small"` or `"large"` | yes | Where the input lives. |
| `encodings` | string[] | yes | Content-Encoding field values as received (may be empty). |
| `input` | object | yes | See below. |
| `limits` | object | yes | See below. |
| `read_pattern` | int[] | no | Read sizes in bytes, applied cyclically. Default `[4096]`. `[1]` = byte at a time. A value of `-1` means "a buffer of MaxOutput+1 bytes, capped at 32 MiB". |
| `options` | object | no | `strict_zlib` (bool, disables the raw-deflate fallback of SG-R-CDC-03), `memory_cap` (bytes, window cap for br and zstd). |
| `expect` | object | yes | See below. |

### `input`

Exactly one form:

- `{"file": "vectors/small/gzip-empty.gz", "sha256": "<hex>"}` committed file.
- `{"generator": {"kind": "...", "params": {...}}, "sha256": "<hex of the generated COMPRESSED stream>"}` generated by the corpus generator. The hash detects encoder drift: a mismatch makes the runner fail with a clear message instead of testing something else.

Generators (initial set; each is deterministic and specified in `spec/generators.md` when implemented): `zeros`, `repeat`, `random_then_zeros`, `chain` (apply codecs in order), `multimember`, `lying_size`, `truncate`, `bitflip`, `header_field`, `window`.

### `limits`

`{"max_output": 1048576, "max_layers": 5, "max_ratio": 1000, "ratio_grace": 65536, "max_input": 4096}`.
Absent keys mean "unset" (defaults apply). `max_ratio: "none"` is the named opt-out. Values are JSON numbers up to 2^53-1; larger limits are written as decimal strings.

### `expect`

Success: `{"outcome": "ok", "length": 1234, "sha256": "<hex of decoded bytes>"}`.

Error:
```json
{ "outcome": "output_limit", "phase": "read", "delivered_at_most": 1048576, "layer": 1 }
```
- `outcome`: one of the outcome classes in SPEC section 2, except `source_error` and `canceled` (not expressible as byte vectors).
- `phase`: `construct` (error before any read: `invalid_limits`, `malformed_encoding`, `unsupported_encoding`, `layer_limit` from the header) or `read`.
- `delivered_at_most` (read phase): upper bound of bytes delivered before the error; MUST NOT exceed `max_output`. Optional `delivered_exactly` where the spec pins it.
- `layer` (optional): 1-based layer index that failed.

## Generators

Inputs described by a generator are built by the construction in `spec/generators.md`, without any compression library, so every language can reproduce them byte for byte. The manifest hash of a generated input detects a deviation. A vector with a generator may have tier `small` (cheap to build) or `large`.

## Runner contract

For each vector: build the input, construct the decoder with `limits`, `encodings`, `options`; if `phase` is `construct`, require the construction error with the right class and zero bytes read from the source; otherwise read with `read_pattern` until a terminal condition; compare outcome class, delivered length bounds and SHA-256. The runner MUST also check: sticky behavior (two more reads after the terminal condition return the same class), and that no more than `max_input` (if set) bytes were taken from the source.

Each vector is additionally run with a fixed set of alternative read patterns (`[1]`, `[3]`, `[4096]`, `[-1]`, `[1,7,4096,1]`) and MUST give identical results (SG-R-RDR-01: the same outcome class and the same decoded prefix; for `ratio_limit` the length of the delivered prefix may differ, which is why those vectors state `delivered_at_most`), unless the vector pins a pattern for a reason stated in `description`.

## Tiers

`small` vectors are committed and always run. `large` vectors (GiB-scale decoded bombs, compressed size around a megabyte) are generated by the corpus generator, listed in the manifest with SHA-256, and shipped in the release tarball. Runners skip `large` vectors when absent unless started with the strict flag; release pipelines run strict.

## Families (initial)

`BOMB` single-layer bombs per codec, `CHAIN` nested chains, `LIE` lying declarations, `WIN` window abuse, `HDR` header attacks, `MAL` malformed/truncated/bit-flipped, `BND` boundary (limit-1, limit, limit+1), `IDN` identity bounds, `MULTI` multi-member and trailing data, `RAT` ratio vectors with margin.

## Rule coverage

`tools/spectrace` extracts every `SG-R-*` and `SG-I-*` ID from `spec/SPEC.md` and reports those not named by a vector's `rules` field or in any `_test.go` file. CI fails on uncovered IDs once the suite is complete.
